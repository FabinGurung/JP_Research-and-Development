Methodological limitations

What the validation does not establish

The methodology is limited to the development and validation of a prototype database system. The current prototype does not yet represent a complete commercial BIM-GIS software platform. The structural analysis module is limited to a simplified Moment Distribution Method example and does not yet include advanced structural analysis, complete building-frame analysis, nonlinear analysis, or full design-code checking. The GIS component is addressed at the framework level and is intended for future extension using PostGIS and official spatial datasets. Similarly, the BIM component is addressed through relational element modeling and IFC-oriented data structure planning, while full IFC import and export are reserved for future development. Despite these limitations, the methodology provides a working foundation for integrated AEC data management and demonstrates how a normalized relational database can support automated workflow connections among structural analysis, architecture, estimation, method statements, specifications, and reporting.

Recommendations

Ten evidence-aligned next steps

These are recommendations from the thesis, not claims that the capabilities already exist.

  1. 01

    The relational database framework should be extended from the current beam-based prototype to a complete building model including slabs, columns, footings, walls, openings, staircases, and other common building elements.

    Future work
  2. 02

    The structural analysis module should be expanded beyond the Moment Distribution Method to include additional load types, multi-span systems, frame action, column behavior, lateral load analysis, and design-code-based checks.

    Future work
  3. 03

    The estimation module should be extended to include formwork area, reinforcement quantity, masonry quantity, plastering, painting, flooring, excavation, PCC, RCC, and other BOQ-related work items.

    Future work
  4. 04

    The BIM component should be further developed through IFC mapping so that relational database elements can be connected with BIM objects and exported or exchanged with BIM-compatible software.

    Future work
  5. 05

    The GIS component should be implemented using PostGIS so that project location, municipal boundary, seismic zoning, soil classification, road access, and other spatial parameters can be connected with building design data.

    Future work
  6. 06

    Construction scheduling should be added as a future module. This should include construction activities, durations, predecessor-successor relationships, early start, early finish, late start, late finish, float, milestones, resources, and Critical Path Method analysis.

    Future work
  7. 07

    The prototype should be tested using a real building project from Pokhara to evaluate practical performance, data consistency, time efficiency, quantity accuracy, and workflow integration.

    Future work
  8. 08

    A user interface should be developed to allow engineers, architects, estimators, and project managers to interact with the database without directly writing SQL queries.

    Future work
  9. 09

    Future work should include security, role-based access control, audit trails, version history, approval workflow, and backup mechanisms so that the system can be used in real professional practice.

    Future work
  10. 10

    The developed framework should be compared with conventional manual workflows to quantify improvements in time, accuracy, consistency, and documentation quality.

    Future work

Future scope

A larger integrated AEC data ecosystem

Future work

The future scope of this study is broad because the implemented prototype represents only the foundation of a larger integrated AEC database ecosystem. The system can be expanded into a full cloud-based platform where BIM, GIS, structural analysis, estimation, scheduling, construction documentation, procurement, payments, vendors, and project history are connected through a single relational database. Future development can also include artificial intelligence-assisted query generation, automatic report writing, automated drawing extraction, code-compliance checking, municipal submission support, and dashboard-based project monitoring. With further development, the proposed framework can contribute to more transparent, consistent, and automated construction workflows in Nepal.

Engineering responsibility

The current prototype does not replace ETABS, SAP2000 or Abaqus. Any future integration would require independent engineering validation, governance, security and professional review.
